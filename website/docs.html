Start here

Begin with the outcome, not the interface.

Allegretto is designed for work that needs both capability and attention. Give it a clear intention in ordinary language, then let it suggest a sequence you can understand before anything consequential happens.

  1. 01

    Name the outcome

    Say what you want to be true at the end. Include the context that changes the answer.

  2. 02

    Review the path

    Look at the proposed tools, dependencies, and side effects. Edit the plan when the route is not right.

  3. 03

    Choose the permission level

    Set Ask, Auto, or Allow all to match the work. In Ask, meaningful actions pause for you; broader modes can let more actions proceed without a prompt.

  4. 04

    Stay in the loop

    Watch progress in context. Pause, redirect, or take control when the situation changes.

Set up Allegretto

Make the first session feel like home.

Allegretto can start with a local model or a provider you connect yourself. These are the useful first five minutes.

  1. 1. Open Settings → Providers & keys.Sign in to a supported provider or add an API key. Keys are kept locally and used to call that provider directly.
  2. 2. Choose Settings → Appearance.Pick the Allegretto theme, then choose Light, Medium, or Dark. The theme carries the warm paper and agency-blue identity into the workspace.
  3. 3. Choose a workspace folder.Use the folder chip at the top of a chat to set where file reads, edits, and commands begin.
  4. 4. Pick a model.Start a chat, use the model picker in the composer, and select the local or hosted model that fits the boundary.
  5. 5. Set permissions before work begins.Use the composer permissions pill for Ask each, Auto approve, or Allow all. Computer control has its separate Settings → Automation choice.

The mental model

One place for the plan, the model, and the boundary.

Allegretto keeps the conversation, context, approvals, and run state on the machine where you are working. It does not ask you to hand your whole workflow to a hidden control plane.

Choose a model

Use local capability when the boundary matters.

Local models are useful when the prompt and response should stay on the device. Hosted models can offer more capability, but the request goes directly to the provider you selected using your credentials.

A practical check

Before sending a hosted request, ask: does this context need to leave the device, and have I reviewed the provider’s current retention and training terms?

  • Local model: prompt and response remain on the device running Allegretto.
  • Hosted model: the provider sees the prompt, relevant context, and tool information needed for that request.
  • Switching: changing models does not have to change your workflows or local context.

Tools and approvals

Let the plan show its work.

Tools are named actions with inputs and outcomes. Workflows show their steps and dependencies before they run, giving you a chance to spot an incorrect assumption while the change is still reversible.

Permission modes matter

Ask pauses for approvals. Auto runs lower-risk commands and asks before riskier ones; MCP tools and computer-control actions still ask in Auto. Allow all removes shell and MCP prompts. Computer control has its own Settings → Automation choice: Ask me first or Full automation, which can run computer actions without pausing. Check both settings before a run.

Browser bridge

Bring the work to the browser you already use.

The browser bridge connects an approved browser context so an agent can read or act where the work already lives. It does not move your sessions into a hosted browser.

  • Connect only the browser profile and page you intend to share.
  • Review the plan before actions involving credentials, purchases, messages, or deletion.
  • Pause the run and take control back whenever a page or intention changes.

Troubleshooting

When the path feels unclear.

The model picker is emptyOpen Settings → Providers & keys and confirm the provider is connected or has a usable API key. For local models, make sure the model has finished downloading and is available on this Mac.
A tool keeps askingCheck the composer permissions pill. Auto approve still asks for riskier commands, MCP tools, and computer control. Check Settings → Automation for the separate computer-control mode.
The browser page is not availableOpen Settings → Chrome and connect the browser bridge to the browser profile you intend to share. The bridge cannot see a page until that connection is active.
The work is in the wrong folderClick the folder chip at the top of the chat and choose the workspace folder again. New sessions in that chat will use the selected folder.
A run is taking too longRead the current tool status before interrupting. Stop the run when the plan is wrong, then revise the request or lower the scope instead of repeating the same path.

Privacy boundary

Know where each part of the work lives.

Allegretto is local-first, not provider-blind. Your choice of model determines which information crosses the device boundary.

On your deviceConversations, drafts, workflow state, preferences, and local model files.
At your providerHosted prompts and responses sent directly under that provider’s terms.
With Virtually(Creative)The product site, not a hidden inference relay or conversation store.

Glossary

The local layer that holds the plan, context, tools, approvals, and run state together.
Provider
The service that runs a hosted model when you choose to send a request there.
Browser bridge
The approved connection between Allegretto and an existing browser context.
